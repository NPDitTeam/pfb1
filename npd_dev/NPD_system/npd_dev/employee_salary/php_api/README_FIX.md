# แก้ปัญหา "หักซ้ำ" ขาด/ออกก่อนเวลา กับ การลา

## ปัญหา
กรณี **30/04/2026** (พนักงาน อรุณ หอมคง รหัส 0435):
- มีใบลา 15:00–17:00 (ลากิจไม่ได้รับค่าจ้าง) → หัก "ยอดหักจากการลา"
- สแกนออก 15:02 → ระบบมองเป็น "ออกก่อนเวลา / ขาด 1ชม 58นาที" → หัก "ยอดหักออกก่อนเวลา/ขาดงาน" อีกรอบ

ช่วงเวลาเดียวกัน (15:00–17:00) ถูกหัก **2 รอบ**

## สาเหตุ

## วิธีแก้ (กฎใหม่)
**ตัดเฉพาะนาทีที่ทับซ้อนกับช่วงเวลาลา ออกจากการคิด สาย/ออกก่อนเวลา**
ครอบคลุม **ทุกใบลาที่อนุมัติ** ของวันนั้น

ตัวอย่าง:
- ลา 15:00–17:00 + ออก 15:02 → ออกก่อนเวลาทับช่วงลาเต็ม → คิดออกก่อนเวลา = 0 (หักแค่ "ลา")
- ลา 15:00–17:00 + ออก 14:30 → คิดออกก่อนเวลาเฉพาะ 14:30–15:00 = 30 นาที + หัก "ลา"
- ลาทั้งกะ → ข้ามการคิด สาย/ออกก่อนเวลา ทั้งวัน

### หักการลา = คิดเป็น "นาที" ตามจริง
`calculateLeaveDeduction()` เดิมปัดเศษชั่วโมงลาขึ้นเป็นชั่วโมงเต็ม (เช่น 37 นาที → 1 ชม.)
เปลี่ยนเป็นคิดเป็นนาทีตามจริง (37 นาที × ค่าจ้างต่อนาที) ให้สอดคล้องกับ สาย/ออกก่อนเวลา
- ลาทั้งกะ → ยังหักเต็มวัน (daily_rate) เหมือนเดิม

# กำหนดสูตรคิดสายเองได้ + วันเริ่มใช้ (เพิ่ม 27/08/2026)

## เดิม
สูตรคิดสายถูกฝังตายตัว = **ผ่อนผัน 15 นาที** (`$grace_period` default 15)
เกิน 15 นาทีถือว่าสาย และนับสายตั้งแต่นาทีแรก (รวม 15 นาทีที่ผ่อนผันด้วย)
แก้ได้อย่างเดียวคือแก้โค้ด ซึ่งจะกระทบยอดที่คำนวณไปแล้วทั้งหมดย้อนหลัง

## ใหม่
เมนู **เงินเดือนพนักงาน > กำหนดสูตรคิดสาย** เด้ง popup ให้ตั้งเองได้

| ตั้งได้ | รายละเอียด |
|---|---|
| ผ่อนผันกี่นาที | ใส่ 0 = ไม่ผ่อนผันเลย |
| เข้างานไม่เกินเวลาไหน | เช่น 08:00 (แทนการนับเป็นนาที) |
| เริ่มใช้วันไหน | **สำคัญ** วันก่อนหน้ายังคิดด้วยสูตรเดิม |

**ค่าเริ่มต้น = ไม่มีสูตรเลย → ระบบใช้สูตรเดิม 15 นาที** ยอดที่คำนวณไปแล้วจึงไม่ขยับ

## วิธีทำงาน
Odoo ส่ง `lateness_rules` (รายการสูตร + วันเริ่มใช้ เรียงจากเก่าไปใหม่) ไปกับ payload
PHP เลือกสูตรของ **แต่ละวัน** เอง ผ่าน `resolveGraceMinutes()`

* ไม่มีสูตรครอบคลุมวันนั้น → ใช้ `$grace_period` เดิมที่ส่งมา
* `mode = grace` → ผ่อนผันตามนาทีที่ตั้ง
* `mode = deadline` → แปลงเป็นนาทีนับจากเวลาเข้ากะ
  (กะเริ่ม 07:30 + เข้างานไม่เกิน 08:00 = ผ่อนผัน 30 นาที)
  ทำแบบนี้เพื่อให้ตรรกะเดิม (หักพักเที่ยง / กันทับซ้อนช่วงลา) ใช้ต่อได้ไม่ต้องแก้

เลือกรายวันแบบนี้ทำให้ **รอบที่คร่อมวันเริ่มใช้คิดถูกทั้งสองช่วงในใบเดียว**
เช่น ตัดรอบ 25/08-24/09 แต่เริ่มใช้สูตรใหม่ 01/09 → 25-31 ส.ค. ใช้สูตรเดิม, 1-24 ก.ย. ใช้สูตรใหม่

## แยกตามสาขาได้ด้วย
สูตรแต่ละอันเลือกได้ว่าใช้กับสาขาไหน — **เว้นว่าง = ทุกสาขา**

วันเริ่มใช้เดียวกัน **สูตรที่ระบุสาขา ชนะ สูตรทุกสาขา** (ชนะเฉพาะสาขาของตัวเอง)
เช่น 01/09 ทุกสาขา = ผ่อนผัน 5 นาที + 01/09 ภูเก็ต = ไม่ผ่อนผัน
→ ภูเก็ตได้ 0 นาที สาขาอื่นได้ 5 นาที

> **การกรองสาขาทำฝั่ง Odoo ทั้งหมด** เพราะสาขาของพนักงานอยู่ที่
> `payroll.salary.branch_id` (related จาก `employee.salary`)
> PHP จึงไม่ต้องรู้เรื่องสาขาเลย รับมาแค่รายการที่กรองแล้วของพนักงานคนนั้น
> — ถ้าจะแก้ตรรกะสาขาในอนาคต แก้ที่ Odoo อย่างเดียว ไม่ต้องแตะ PHP

มี `@api.constrains` กันตั้งซ้อนกัน: วันเริ่มใช้เดียวกันห้ามมีสูตรที่ขอบเขตสาขาทับกัน

## ไฟล์ที่แก้ (ต้องอัปโหลดทับบน npdhrms.com)

   เปลี่ยนเงื่อนไขจาก `$lateMin > $grace_period` เป็น `$lateMin > $grace_today`

## หน้าสรุปเพิ่ม 2 คอลัมน์ + แก้ให้ตัวเลขตรงกับยอดหักจริง

`lateness_summary.php` เพิ่มคอลัมน์ **"สายกี่นาที"** และ **"สูตรที่ใช้"**
(ไม่ต้องเพิ่มคอลัมน์ใน DB — คำนวณจาก `checkin_logs` + สูตรที่ส่งมาทาง URL)

ตารางเป็น 11 คอลัมน์:
`ชื่อ | สาขา | ประเภท | วันที่ลงเวลา | แผนก | ตำแหน่ง | ละติจูด | ลองจิจูด | สายกี่นาที | สูตรที่ใช้ | สถานะ`

คอลัมน์ "สูตรที่ใช้" แสดงเช่น `ผ่อนผัน 15 นาที` / `ไม่ผ่อนผัน` /
`เข้างานไม่เกิน 08:00 (= ผ่อนผัน 30 นาที)` / `สูตรเดิม (ผ่อนผัน 15 นาที)`
ทำให้ตรวจได้ว่าเลขนาทีนั้นมาจากสูตรไหน

### ⚠️ แก้บั๊กที่มีมาก่อนหน้า: หน้าสรุปเคยไม่ตรงกับยอดหักจริง
เดิมหน้าสรุปเอา **เวลาดิบ** ไปเทียบกับ `shift_start + grace` ก่อน
แต่ `calculate_lateness.php` หักพักเที่ยง + ตัดช่วงลา **ก่อน** ค่อยเทียบกับ grace
วันที่มีใบลาคาบเกี่ยวจึงไม่ตรงกัน เช่น

| เคส (ผ่อนผัน 15 นาที) | payroll หักจริง | หน้าสรุปเดิม |
|---|---|---|
| ลา 08:00-09:00 เข้า 09:05 | 0 นาที | **สาย 5 นาที** |
| ลา 08:00-08:30 เข้า 08:40 | 0 นาที | **สาย 10 นาที** |
| ลา 08:00-08:20 เข้า 08:25 | 0 นาที | **สาย 5 นาที** |

แก้ให้หน้าสรุปคิดลำดับเดียวกับตัวคำนวณแล้ว ตัวเลขสองที่ตรงกันทุกเคส

## แอปมือถือ: แสดง "สายกี่นาที" ใต้เวลาเข้างาน + เห็นผลของวันนี้ทันที

แอป (hrms_npd) เรียก Odoo ผ่าน JSON-RPC:
`payroll.lateness.rule.api_get_late_minutes(employee_code, month, year)`
→ Odoo ประกอบสูตร + ตารางกะ แล้วยิงมาที่ `calculate_lateness.php` ตัวนี้
→ คืน `{'YYYY-MM-DD': นาที}` ให้แอปแสดง

ตัวเลขที่แอปโชว์จึงเป็น **นาทีเดียวกับที่ payroll หักจริง** ไม่ได้คำนวณซ้ำในแอป
และเปลี่ยนสูตรใน Odoo ปุ๊บ แอปตามทันทีโดยไม่ต้องอัปแอปใหม่

### flag `include_today`
เดิมลูปคำนวณข้าม "วันนี้" ทิ้ง (`if ($cursor >= $today)`) เพราะวันยังไม่จบ
ยังไม่สแกนออก ถ้าคิดเลยจะกลายเป็น "ขาดงาน/ออกก่อนเวลา" ทั้งวัน
ผลข้างเคียงคือ **สายของวันนี้ก็ไม่ถูกนับ** พนักงานต้องรอถึงพรุ่งนี้ถึงจะเห็น

เพิ่ม flag `include_today` ใน payload

| ผู้เรียก | ส่ง flag | ผลลัพธ์ |
|---|---|---|
| payroll (`payroll.salary`) | **ไม่ส่ง** | เหมือนเดิมทุกประการ ยอดหักไม่ขยับระหว่างวัน |
| แอป (`api_get_late_minutes`) | `true` | เห็นสายของวันนี้ทันทีที่สแกนเข้า |

เงื่อนไขใหม่ `$cursor > $today || ($is_today && !$include_today)`
เมื่อ `include_today=false` จะยุบเหลือ `$cursor >= $today` = **ของเดิมเป๊ะ**
(ทดสอบเทียบ 55 วันแล้วให้ผลตรงกันทุกวัน)

ตอน `include_today=true` วันนี้จะเข้าบล็อก `if ($is_today)` ซึ่ง
* คิดเฉพาะ "สายเข้างาน" จาก checkin (ยังไม่มี checkout ก็คิดได้)
* **ไม่แตะ** ขาดงาน / ออกก่อนเวลา
* **ไม่บวกเข้า** `$total_lateness` / `$total_late_in` ที่ใช้คิดเงิน
* ติดธง `'today' => true` ใน `late_checkin_log` ไว้แยกแยะ

> ⚠️ ผลที่ตามมาโดยตั้งใจ: แอปจะโชว์สายของวันนี้ แต่ยอดในสลิป/รายงาน
> จะยังไม่รวมจนกว่าจะผ่านวันไปแล้ว — ต่างกันได้ 1 วันเป็นเรื่องปกติ
